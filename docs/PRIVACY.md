# 匿名互动计数与隐私

宣传页仅记录随机事件编号、项目编号、当前发布版本编号、来源（二维码 qr / 普通链接 link）、互动类型（浏览 view / 拨号 call / 复制微信号 wechat_copy / 导航 navigate）以及服务器 UTC 时间。不记录 IP、IP 哈希、User-Agent、Cookie、设备标识、精确位置或顾客身份；不会为统计设置 Cookie。

这是**匿名、可能被刷的互动计数**，用于观察趋势，不代表独立访客、实际通话、成功导航、精确转化率或商业收入。对外材料必须保留这一口径。来源由 URL 的 `src=qr` 决定；点击计数不证明后续动作成功。

## 去重、限流和代理前提

同一「进程随机盐 HMAC-SHA256(IP) + slug + action」10 秒内仅计一次；同键每 60 秒最多处理 30 次合法请求尝试（重复事件也消耗预算）。切换 source 或 versionId 不重置键。只有当前已发布且未删除、未下线的版本能写入，检查与写入位于同一 SQLite 事务。

IP 只用于立即计算进程内的带盐哈希，不写入数据库或应用日志。内存键最多 10,000 个，容量满时拒绝新键而不驱逐仍有效的限流状态；到期清理，进程重启全部重置。计数无法阻止分布式刷量，也可能低估共享网络用户。

默认 `TRACK_TRUST_PROXY=false`：Next.js Route Handler 不提供可信 socket 地址，因此忽略所有转发头，使用共享 unknown 桶（仍按 slug/action 区分），可能明显低估访问。需要按真实地址区分时，部署者必须先确保应用端口仅对受信代理开放，并由最后一层代理**覆盖** `X-Real-IP` 为验证过的客户端地址、拒绝客户端原值，再设置 `TRACK_TRUST_PROXY=true`。不读取 `X-Forwarded-For` 链；非法或多地址头归入 unknown 桶。部署代理信任链必须另行实测。

不记录请求体或访问标识的应用日志不代表反向代理、CDN、托管平台也不记录；部署时需自行关闭或脱敏其访问日志，避免保存 IP、UA、Cookie 等信息。

## 统计与导出

`GET /api/projects/:id/stats?days=7` 需要管理鉴权。days 是 1–365 的整数，默认 7：按 Asia/Shanghai（UTC+8）取今天及之前 days-1 个自然日，截至请求时刻，空日期补零。totals 是各动作合计；bySource 汇总所有动作的来源；daily 是每日各动作次数。项目列表 views7d 使用同一窗口，只计 view。历史发布版本已入库的事件继续计入项目统计，旧版本的新上报则被拒绝。

`pnpm -s stats:export <projectId> > stats.csv` 在服务器本地导出该项目全部保留事件的北京时间每日汇总（date,view,call,wechat_copy,navigate,qr,link），仅列有事件的日期。CSV 没有身份信息与原始请求；输出到 stdout，错误写入 stderr。命令使用 `.env.local` 的 DATA_DIR，直接访问本地数据库，因此仅应交给有服务器文件权限的管理者。

## 删除和预览

删除项目时，同一数据库事务将项目标记删除并清除全部 visit_events；此后拒绝任何新上报。统计文件导出和部署者自行保存的备份需要另外删除。

预览响应将 body 的 data-track 置为空字符串，并使用 connect-src 'none'；不改动不可变版本文件和脚本字节，也不产生埋点。

## 发布和缓存

服务端每个公开 HTML/图片请求都按当前 publishedVersionId 读取。HTML 依规格使用 `public, max-age=60, stale-while-revalidate=600`：浏览器或代理可能仍展示旧页面，发布/下线不保证缓存即时失效，离线或已打开页面也不会被远程撤回。缓存的旧页面所报旧 versionId 会被忽略，可能少计。

公开图片 URL 不含版本号，采用 no-store；跨请求切换发布版本时，旧 HTML 的图片请求可能读取新版本同名图片或 404，不能保证整次浏览跨请求原子一致。预览和错误响应不缓存。正式微信扫码、拨号及公网代理日志配置需在部署后实机验证。

## 顾客纠错

宣传页底部的「信息有误？告诉老板」表单只收集：哪一项有误（事实路径，如 `items.<id>.price`、`shop.hours` 或 `other`）、顾客建议的正确值（≤100 字）、补充说明（选填，≤200 字），以及提交时间和所在页面版本。不要求、也不记录任何联系方式或身份信息：没有姓名、手机号、IP、IP 哈希、User-Agent 或 Cookie。

- **主动拒绝个人信息**：建议值与补充说明中出现手机号、座机号、邮箱、带提示词的微信号或身份证号时，提交直接被拒绝（400「请勿填写个人信息」），内容不会入库。电话和微信两项只提供「联系不上或有误」选项，不提供输入框，由商家自行核实。
- **内容过滤**：去除 HTML 标签与控制字符；含链接或明显广告词的提交标记为垃圾（`spam`），仍入库以便统计滥用，但不出现在商家后台。
- **限流**：只有通过全部校验、即将入库的报告才计数：同一「进程随机盐 HMAC-SHA256(IP) + 项目」每 10 分钟最多 3 条，每个项目每天最多 50 条；指向不存在页面或被拒绝的请求不计数、不占用限流器容量。未配置可信代理（`TRACK_TRUST_PROXY=false`）时所有访客共用同一来源桶，即每个页面每 10 分钟最多 3 条，正式部署须按上文配置代理；IP 只在内存中用于计算哈希，不落库、不写日志。代理前提与访问统计相同（`TRACK_TRUST_PROXY`）。
- **用途**：商家逐条采纳或忽略。采纳 = 用商家确认的值生成新的商品信息版本并重新渲染发布，二维码和链接不变，不调用任何模型。被采纳与被忽略的记录用于评估「AI 识别与人工填写在哪里出错」，`pnpm corrections:export > corrections.jsonl` 在服务器本地导出全部记录（只有上述字段）。
- **保留与删除**：纠错记录随项目保留；删除项目时在同一数据库事务中删除该项目的全部纠错记录。导出文件和部署者自行保存的备份需要另外删除。
